Feature: Grid Trade Performance report (PDF) — DEMO-COOP Reverse Grid, as of 06 Nov 2026

## Background

The Quant team sends each Reverse Grid client a five-page PDF, "Reverse Grid Trading Performance". It shows the account summary, every transaction, and one page per instrument with two charts. This issue asks for that report, generated by code from the mock fixture `data/fixtures/demo_grid_2026_11/` (merged in #22). Every value in the fixture is invented.

Code computes and checks every figure. The report must not contain a number that does not come from the fixture or from a formula in this spec. There is no narrative text in this report.

Build on the data layer on `main`: `DataSource`, `FixtureSource`, `SqliteSource`, the schema registry and the Layer A checks in `quant_software_factory.reporting`. Do not change the behavior of the existing `returns_transactions` report: its committed outputs in `reports/demo_coop_rg_2026_10_v2/` must regenerate byte for byte.

## Data Sources

Read `data/fixtures/demo_grid_2026_11/` only through a `DataSource` (`FixtureSource` for the committed output). Do not change the fixture. Datasets: `account_info`, `grid_setup`, `holdings_daily`, `grid_cash`, `nav_daily`, `transactions`. The folder's `README.md` describes every field and convention.

Register the new datasets in `SCHEMAS`:
- `grid_setup`: `account_no` str, `instrument` str, `display_order` int, `initial_units` int, `initial_cost` decimal, `commission_rate` decimal, `expected_trade_units` int, `expected_trade_return_pct` decimal. No date field: return all rows for the account.
- `grid_cash`: `date` date, `account_no` str, `instrument` str, `cash` decimal.
- `transactions.side`: add `PORT_ADJUSTED` and `GAIN_ADJUSTMENT` to the allowed values.

## Formulas

All arithmetic uses `decimal.Decimal`, ROUND_HALF_UP, and rounds only for display.

- Expected volume = `cash / (market_price × (1 + commission_rate))`, rounded down to a whole lot of 100 shares.
- NAV volume = current units + expected volume.
- Gain volume = NAV volume − initial units.
- Current units change % = (current units / initial units − 1) × 100.
- Cost change % = (avg cost / initial cost − 1) × 100.
- Approximate initial cost value = initial units × initial cost.
- Weight % = market value / NAV × 100, for each instrument and for CASH.
- Cash % = cash on hand / NAV × 100.
- Dividend (YTD) = sum of DIVIDEND `amount` with a date in the as-of year, up to the as-of date.
- NAV volume % on date d = ((volume_d + expected volume_d) / initial units − 1) × 100, using that date's `holdings_daily` and `grid_cash`.

Colours: text `#111827`; secondary text `#6B7280`; borders `#E5E7EB`; accent navy `#1E3A8A`; label blue `#1D4ED8`; positive green `#15803D`; negative red `#DC2626`; page background white; panel background white with a rounded border (radius 3 mm).

## Formats

- whole number: thousands separators, no decimals (cards and the initial cost value)
- money and prices: 2 decimals, thousands separators
- units: integer with thousands separators
- percent: as stated per field, followed by `%`
- dates in tables `YYYY-MM-DD`; inception `DD Mon YYYY`; header `DD Month YYYY`
- negative values with a leading `-`; `-0.00` printed as `0.00`

- Command: `python -m quant_software_factory.reporting.grid_performance data/fixtures/demo_grid_2026_11 reports/demo_grid_2026_11 --account DEMO-0001 --as-of 2026-11-06 --generated-at 2026-11-06T18:00:00Z`
- Writes to the output folder:
  - `report.pdf`
  - `report.json`: every value printed in the PDF, keyed by page and block, numbers as the formatted strings shown in the PDF, plus the chart series as formatted strings
  - `checks.json`: Layer A and Layer B results in the existing `{name, layer, passed, expected, actual}` format, sorted by name
- If any check fails: exit 1, write `checks.json` only, and remove stale `report.pdf` and `report.json`.
- Two runs with the same arguments give byte-identical `report.pdf`, `report.json` and `checks.json` (set the PDF creation date from `--generated-at`).
- Commit the three generated files.
- Add `fpdf2==2.8.9` as a runtime dependency in `pyproject.toml`. The PDF library is used only to draw the page; all figures are computed before drawing.

## Number Checks

Layer A (data), for the six datasets: schema, required values present, the as-of date present for every instrument in `holdings_daily`, `grid_cash` and `nav_daily`, and `holdings_daily` and `grid_cash` each have one row per instrument per date.

Layer B (report):
- G1 NAV: sum of instrument `market_value` + sum of `grid_cash.cash` = `nav_daily.nav` on every date; `nav_daily.cash` = sum of `grid_cash.cash`.
- G2 holding rows: `cost_value = volume × avg_cost` (0.01), `market_value = volume × market_price`, `unrealized_pl = market_value − cost_value`, on every row.
- G3 same figure everywhere: the NAV card equals the Total market value; the Cash card equals the CASH row; each instrument's page-1 values equal its own page.
- G4 units reconcile: `initial_units` + BUY qty − SELL qty up to each date = `holdings_daily.volume` on that date.
- G5 weights: the instrument and CASH weights sum to 100.00 (tolerance 0.01 before rounding).
- G6 grid volumes: NAV volume = current units + expected volume; gain volume = NAV volume − initial units.
- G7 dividend YTD equals the sum of the dividend rows it counts.
- G8 transactions: page 2 has min(25, rows up to as-of) rows; each instrument page has min(7, that instrument's rows) rows; all shown rows exist in `transactions`.
- G9 charts: each series has one point per history date, starting at the inception date and ending at the as-of date.
- G10 PDF: page count = 2 + number of instruments.

Tolerance 0.01 per value unless stated. Compare unrounded `Decimal` values.

## Constraints

- Report figures and checks: standard library only. `fpdf2` is the only new dependency and only draws the PDF.
- Draw charts with fpdf2 primitives (lines, rectangles, text). No plotting library.
- No network, no LLM call at runtime.
- No real client data, logos or company names.
- Keep `ruff check`, `ruff format --check`, `mypy` (strict) and `pytest` green on Python 3.10 to 3.13.

## Tests

- Regenerating the report from the fixture gives files identical to the committed `reports/demo_grid_2026_11/` files.
- The same report built through `SqliteSource` (load the six fixture CSVs into a temporary SQLite database in the test) gives byte-identical `report.json` and `report.pdf`. This simulates reading from a database.
- Every Expected Values row is asserted against `report.json`.
- Each Layer B check fails on a broken copy of the fixture (one case per check).
- The existing `returns_transactions` outputs still regenerate unchanged.

## Out of Scope

- Narrative text, logos and brand styling.
- Real data, the private-data executor, and the Discord report agent.
- Forecasts or recommendations.
- Program Trading and other report types.
